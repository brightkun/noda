Ветка — подвижный указатель на коммит. Новая работа идёт в отдельной ветке, а `main` остаётся рабочим.

Основной цикл: `git switch -c feature/name`, коммиты, `git push`, pull request, ревью, merge. Перед слиянием полезно подтянуть свежий `main`, чтобы конфликты решать у себя.

merge сохраняет историю как есть, rebase переписывает коммиты поверх другой ветки и делает историю линейной. Rebase нельзя делать для веток, которые уже забрали другие.

Хорошее сообщение коммита отвечает на вопрос «что и зачем». Проверку pull request автоматизирует [[CI-CD]]. Файлы с секретами в репозиторий не добавляют, их исключает `.gitignore`.

Частая ошибка: закоммитить `.env`. Из истории он не исчезает, ключ придётся менять.
