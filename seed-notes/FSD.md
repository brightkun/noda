Feature-Sliced Design — способ раскладывать фронтенд по слоям, чтобы проект не превращался в кашу.

Слои сверху вниз: `app` → `pages` → `widgets` → `features` → `entities` → `shared`.

Правило: слой импортирует только из слоёв ниже себя. `entities` не знает про `features`, `shared` не знает ни про кого. Внутри слоя срезы (slices) не импортируют друг друга.

Пример для заметок:
- `entities/note`: тип `Note`, карточка заметки, запросы
- `features/generate-questions`: кнопка и логика генерации вопросов
- `widgets/knowledge-graph`: граф связей
- `shared/ui`: кнопки и инпуты без бизнес-логики

В срезе обычно есть `ui/`, `model/`, `api/` и публичный `index.ts`: снаружи импортируют только из него.

Для Next.js папку `app/` оставляют под роуты, а слои FSD кладут в `src/`, см. [[Next.js рендеринг]]. Запросы к API внутри срезов удобно оборачивать в [[React Query]], типы описывать по [[TypeScript типы]].

Частая ошибка: импорт «вверх» (например, из `features` в `entities`), из-за которого появляются циклы.
