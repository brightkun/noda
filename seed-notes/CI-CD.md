CI (continuous integration) — автоматическая проверка каждого коммита: установка зависимостей, линтер, проверка типов, тесты, сборка. CD (delivery или deployment) — автоматическая выкатка проверенной версии.

В GitHub Actions пайплайн описывается файлом в `.github/workflows`: событие запуска (push, pull request), шаги, окружение. Секреты хранятся в настройках репозитория и подставляются как переменные, в код они не попадают.

Для проекта на [[Docker]] типичный пайплайн: проверка → сборка образа → публикация → деплой. Работа по веткам и pull request описана в [[Git ветки]].

Частая ошибка: вывести секрет в лог шага.
